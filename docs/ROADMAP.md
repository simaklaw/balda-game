# Дорожная карта

## Этап 0 — Инфраструктура
- [x] Каркас монорепо (client / server / shared / docs)
- [x] Vitest + ESLint + Prettier
- [x] GitHub Actions CI (lint + test)

## Этап 1 — Ядро игры (shared/, чистый TS, без UI)
- [x] Модель: Board (3×3/5×5/7×7), ход, счёт, состояния партии
- [x] Валидация хода: соседство (орт./диаг.), новая буква, слово в DAWG
- [x] DAWG: реализация структуры, сериализация, сборка из word-list
- [x] ИИ-соперник: перебор с эвристикой (easy / medium / hard)
- [x] Юнит-тесты правил, словаря, игры и ИИ
- [x] Источник словаря: Harrix/Russian-Nouns → `client/public/dict/words.txt`
      (49 312 слов; сверка со словарём Зализняка — последующая задача, см. docs/DICTIONARY.md)
- [x] Поражение по времени: `Game.declareTimeout`, EndReason 'timeout'

## Этап 2 — UI на PixiJS (client/)
- [x] Vite + TypeScript + PixiJS-каркас
- [x] Экраны: меню → игра → результат (FSM)
- [x] Поле, drag-to-select + пошаговый клик
- [x] Кастомная canvas-клавиатура (системная клавиатура не используется)
- [x] Оффлайн-режим против ИИ (3×3 «бал» / 5×5 «балда», сложность easy/medium/hard)
- [x] Таймеры: 2 мин на ход (авто-пас), блиц и Фишер (поражение по времени)
- [x] История ходов: панель со списком слов и очков
- [x] Тёмная/светлая тема, выбор сохраняется через платформенное хранилище
- [x] Mobile-first: safe-зоны (челка/жест-бар), адаптивная вёрстка меню и партии
      под 320–1920px, пауза часов при сворачивании, крупные тап-таргеты
- [x] Толковый словарь по клику на слово в истории (Викисловарь, загрузка по
      требованию, кэш в localStorage, атрибуция CC BY-SA)
- ✅ UX-полировка: автоотправка слова при обводке пальцем, ход бота с подсветкой пути и словом в статусе, анимации pop/тряска, подсказки «+» на доступных клетках, «+N» у превью слова, правила в меню
- [ ] 60 FPS на слабых устройствах; доводка ландшафтного режима на телефонах

## Этап 3 — SDK Abstraction Layer → первый релиз
- [x] Интерфейс PlatformAdapter: ready, getPlayerName, showInterstitial, storage
      (rewarded-видео, платежи, лидерборды — следующие шаги, см. docs/PLATFORM.md)
- [x] Веб-адаптер (localStorage, без рекламы) + фабрика createAdapter
      с определением площадки по URL/user-agent
- [x] Яндекс Игры: LoadingAPI.ready, межстраничная реклама между партиями
      (не чаще раза в 3 минуты), облачное хранилище игрока с фолбэком на
      localStorage; 13 тестов платформенного слоя
- [x] Яндекс Игры: локальный рейтинг оффлайн-партий — топ-10 личных результатов
      в облачном хранилище игрока, кнопка «Рейтинг» в меню; публикация
      черновика — пошаговая инструкция docs/PUBLISH_YANDEX.md
- [x] VK Bridge (VK Mini Apps): VKWebAppInit, имя игрока (VKWebAppGetUserInfo),
      облачное хранилище VKWebAppStorage с фолбэком на localStorage,
      нативная interstitial-реклама; определение площадки по URL (vk_app_id,
      vk.com/vk.ru); ~24 теста платформенного слоя
- [x] Telegram WebApp (Mini Apps): ready/expand, имя игрока (initDataUnsafe),
      облачное CloudStorage с фолбэком и страховочным таймаутом; скрипт
      telegram-web-app.js в index.html; определение площадки (t.me, tgWebApp*)
- [x] Одноклассники: новые игры публикуются только через VK Mini Apps
      (apiok.ru, ok-js-sdk заморожен с 2019), VK-адаптер покрывает OK;
      ok.ru распознаётся как VK-платформа

## Этап 4 — Мультиплеер (server/)
- [x] Authoritative-сервер: Node.js + ws, комнаты (быстрый матч, приватная по
      коду), серверная валидация ходов через ядро shared/ (Game + DAWG);
      клиент присылает только путь, клетку и букву
- [x] Таймер хода 2 мин с авто-пасом; техпоражение при 3 пропусках подряд
- [x] Reconnect Window 45 сек с секрет-токеном сессии (защита от угона слота);
      техпоражение по истечении окна реконнекта
- [x] Серверный DAWG из shared/: загрузка `client/public/dict/words.txt`
      (env DICT_PATH), fallback-набор при недоступности файла
- [x] Юнит-тесты комнат и матчмейкинга (Vitest)
- [x] Эло-рейтинг (K=32) и фишки за победу: сервер пересчитывает при завершении
      партии, рейтинг по имени игрока (файловое хранилище); дельты приходят
      клиенту в сообщении game-over
- [x] Клиент: NetClient (WS, сессия в хранилище платформы, авто-reconnect),
      лобби (быстрый матч, комната по коду на canvas-клавиатуре), онлайн-партия
      с таймером хода, подсветкой хода соперника и экраном результата
      с дельтами рейтинга и фишек
- [x] Постоянное хранение: профиль игрока на сервере (JSON-файл, env
      PLAYERS_PATH, атомарная запись tmp+rename, миграция старого формата
      «число = рейтинг», устойчивость к битому файлу); graceful shutdown
- [x] Выдача профиля клиенту: команда profile в протоколе (PlayerProfile),
      кнопка «Профиль» в лобби с оверлеем (рейтинг, фишки, партии, победы,
      винрейт)
- [x] Деплой: Dockerfile + docker-compose (том /data для профилей, healthcheck),
      WSS за обратным прокси — docs/DEPLOY.md; CI-джоба docker build
- [ ] БД/Redis при росте нагрузки
